STEP 1 — Detect gaps
Run: ./venv/Scripts/python.exe manage.py find_metadata_gaps --path scripts/metadata_gap_queue.json --limit 25
This overwrites scripts/metadata_gap_queue.json with up to 25 artists, 25 songs, and 25 albums that are each missing at least one enrichable field. Read that file.

If artists, songs, and albums are ALL empty: print "Nothing to enrich this run." and STOP. Do not proceed further.

STEP 2 — Research each queued record
For every record in the queue, use web search to find values for exactly the fields listed in its "missing_fields" array. Nothing else.

Field meanings:
- Artist: country (full name), country_code (ISO 3166-1 alpha-2, e.g. KE, TZ, NG, US), city_region (city/region of origin), genre, biography (2-4 sentences, neutral factual tone, no marketing fluff), spotify_url, apple_music_url, youtube_url, boomplay_url, audiomack_url, tiktok_url, instagram_url, x_url, facebook_url, website_url (the artist's own official channel URLs, not a search results page).
- Release (song/album): country, country_code, genre, label, distributor, spotify_url, apple_music_url, boomplay_url, audiomack_url, youtube_url, tiktok_url, shazam_url. Songs additionally: songwriters, producers, isrc. Albums additionally: number_of_tracks, upc. Both additionally: release_year, release_date (YYYY-MM-DD, only if you can confirm the exact day).

Sourcing rules (match the standard this project already holds itself to — see the reasoning in scripts/metadata_research_*.json and charts/management/commands/update_artist_countries.py if you want examples of the expected quality bar):
- Prefer official platform artist/release pages (Apple Music, Spotify, Shazam, Audiomack, Boomplay, YouTube Music), the artist's own official website/socials, Wikipedia, MusicBrainz, or reputable music press (e.g. musicinafrica.net for African acts, AllMusic, Genius).
- Only include a field in your output if you found it from a source you'd call reasonably reliable. If you can't confirm a field with a real source, LEAVE IT OUT of that record entirely — do not guess, do not infer from the artist's name/nationality stereotypes, do not fabricate URLs. An incomplete-but-correct record is fine; a wrong or made-up value is not.
- Never touch identity/merge decisions: don't flag or attempt to merge possible duplicate artists, and never suggest setting an artist's "verified" flag — those stay human-only, exactly as apply_researched_metadata.py's own docstring already requires.
- Skip a record entirely (omit it from your output) if it turns out not to be a real artist/release (e.g. a generic sound-effects/ambience catalog name) rather than guessing a country for it.

STEP 3 — Write the research payload
Compose one JSON file at scripts/metadata_research_auto_<UTC timestamp, format YYYYMMDD_HHMMSS>.json with this exact shape (only the fields you actually found go in each row; always keep "id" and the row's original name/title/artist):

{

Omit any record you found nothing usable for (don't include an empty row).

STEP 4 — Apply it locally
Run: ./venv/Scripts/python.exe manage.py apply_researched_metadata --path scripts/metadata_research_auto_<same timestamp>.json --apply
This only ever fills currently-blank fields and never overwrites an existing value, so it's safe even if your research disagrees with something already on file. It also skips any row where the live record's name/title no longer matches what you recorded in step 3 (an identity-drift safety net) — that's expected behavior, not an error.
